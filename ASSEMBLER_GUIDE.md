# Руководство программиста по ассемблеру i8080

Встроенный двухпроходный ассемблер Intel 8080 с препроцессором, поддержкой
макросов, условной сборки, объектных файлов и линковщика.

- **Исходный код ассемблера:** `assemble8080/`
  - `assembler.py` — двухпроходный ассемблер
  - `preprocessor.py` — препроцессор (#include, #define, #if, MACRO, REPT)
  - `numbers.py` — парсер числовых литералов
  - `objfile.py` — формат объектных файлов (`.obj`)
  - `linker.py` — линковщик (`.lnk`-скрипты, relocation)
  - `mapfile.py` — генерация/разбор map-файлов
- **Рабочие примеры:** [`assembler_example/`](assembler_example/README.md)
- **GUI:** вкладка «Ассемблер» (сборка, Assemble → OBJ, Link) и «Дизассемблер» (Load Map)
- **Automation API:** функции `asm_*` в `i8080_ci/automation.py`

## 1. Архитектура и принцип работы

Ассемблер работает в **три стадии**:

```
исходный текст (.asm)
        │
        ▼
┌─────────────────────┐
│  1. Препроцессор     │  #include, #define, #if, MACRO, REPT, #path
└─────────────────────┘
        │  (развёрнутый текст)
        ▼
┌─────────────────────┐
│  2. Первый проход    │  сбор таблицы меток/символов (адреса)
└─────────────────────┘
        │  (таблица символов)
        ▼
┌─────────────────────┐
│  3. Второй проход    │  генерация байтов, отслеживание relocation
└─────────────────────┘
        │
        ▼
   AsmResult (binary, symbols, exports, imports, relocations, listing)
```

**Двухпроходность** нужна для разрешения перекрёстных ссылок: метка может
использоваться до её определения (например, `JMP loop`, а `loop:` ниже).
В первом проходе вычисляются адреса всех меток, во втором — генерируются
байты с уже известными адресами.

**Результат сборки** — объект `AsmResult`:

| Поле | Тип | Описание |
|------|-----|----------|
| `success` | bool | Успешность сборки |
| `binary` | bytes | Сгенерированные байты (от `origin`) |
| `origin` | int | Базовый адрес (из `ORG`) |
| `symbols` | dict | `{имя: абсолютный_адрес}` |
| `errors` | list | Список ошибок (`AsmError`) |
| `warnings` | list | Список предупреждений |
| `listing` | list | `[(адрес, байты, исходная_строка)]` |
| `exports` | list | Экспортируемые символы (`EXPORT`) |
| `imports` | list | Импортируемые символы (`IMPORT`) |
| `relocations` | list | `[(offset, size, symbol)]` — точки патча для линковщика |

## 2. Быстрый старт

### Минимальная программа

```asm
        ORG 0x0100
start: MVI A, 0x42
       OUT 0x01
       HLT
```

### Сборка из Python

```python
from assemble8080.assembler import assemble

with open('hello.asm', encoding='utf-8') as f:
    src = f.read()

result = assemble(src, filename='hello.asm')
if result.success:
    print(f"OK: {len(result.binary)} байт, origin=0x{result.origin:04X}")
    with open('hello.bin', 'wb') as f:
        f.write(result.binary)
else:
    for e in result.errors:
        print(e)
```

### Сборка из GUI

1. Откройте вкладку **«Ассемблер»**.
2. Загрузите `.asm` файл (кнопка **Load**) или введите код вручную.
3. Нажмите **Assemble** — результат (байты, символы, listing) появится в панели.
4. Кнопка **Load to Memory** загружает бинарник в память эмулятора.
5. Кнопка **Assemble → OBJ** сохраняет объектный файл (для линковки).
6. Кнопка **Link** слинковывает объектные файлы по `.lnk`-скрипту.

Подробности по GUI — в [разделе 9](#9-инструменты-gui-api-mcp).

## 3. Синтаксис

### 3.1. Строки и комментарии

- **Комментарий** — всё после `;` до конца строки (вне кавычек).
- **Полностью-commented строка** — начинается с `;` или `*`.
- **Shebang** `#!...` в начале файла игнорируется (преобразуется в комментарий).

```asm
        MVI A, 5      ; загрузить 5 в A
; это комментарий
* тоже комментарий
```

### 3.2. Метки

Метка ставится в начале строки, перед инструкцией/директивой.

| Формат | Пример | Область видимости |
|--------|--------|-------------------|
| `имя:` | `loop:` | локальная метка |
| `имя::` | `main::` | глобальная метка |
| `имя` (без `:`) | `loop MVI A,1` | локальная (для совместимости) |

- Имя метки: `[A-Za-z_][A-Za-z0-9_$]*`.
- Метки **регистронезависимы** (внутренне хранятся в верхнем регистре).
- Метка без двоеточия распознаётся, только если слово не является мнемоникой
  или зарезервированной директивой.

```asm
start:  MVI A, 0
loop:   DCR A
        JNZ loop
        RET
```

### 3.3. Числовые форматы

| Формат | Пример | Значение |
|--------|--------|----------|
| Шестнадцатеричный с префиксом | `0x1A`, `0X1A` | 26 |
| Шестнадцатеричный с суффиксом | `1AH`, `1Ah`, `01AH` | 26 |
| Десятичный | `26`, `26d`, `26D` | 26 |
| Двоичный | `11010B`, `11010b` | 26 |
| Восьмеричный | `32q`, `32o` | 26 |

> **Важно:** шестнадцатеричный с суффиксом `H` должен **начинаться с цифры**.
> `0FFH` — корректно, `FFH` — нет (нужно `0FFH` или `0xFF`).

Подробности — в [разделе 11](#11-приложение-числовые-форматы-и-выражения).

### 3.4. Выражения

Операнды инструкций и директив — арифметические/битовые выражения:

| Оператор | Операция |
|----------|----------|
| `+` `-` `*` `/` | арифметика |
| `%` или `MOD` | остаток от деления |
| `AND` | побитовое И |
| `OR` | побитовое ИЛИ |
| `XOR` | побитовое исключающее ИЛИ |
| `NOT` | побитовое НЕ |
| `SHL` / `<<` | сдвиг влево |
| `SHR` / `>>` | сдвиг вправо |
| `EQ`/`==`, `NE`/`!=`, `GT`/`>`, `LT`/`<`, `GE`/`>=`, `LE`/`<=` | сравнение |
| `HIGH(x)` / `LOW(x)` | старший/младший байт |
| `$` | текущий адрес (PC) |

```asm
        MVI A, HIGH(0x1234)   ; A = 0x12
        MVI B, LOW(0x1234)    ; B = 0x34
        MVI C, 1 << 4         ; C = 16
        MVI D, 0xFF AND 0x0F  ; D = 0x0F
```

## 4. Директивы ассемблера

Директивы управляют расположением кода/данных и таблицей символов.
Большинство работают и с точкой (`.ORG`), и без (`ORG`).

### 4.1. `ORG` — базовый адрес

Устанавливает адрес, с которого начинается генерация байтов.

```asm
        ORG 0x0100
```

- Первый встреченный `ORG` определяет `origin` результата сборки.
- Повторный `ORG` меняет текущий адрес (можно «перескочить»).
- Если `ORG` нет, `origin = 0x0000`.

### 4.2. `DB` / `DM` / `BYTE` — байты данных

Записывает байты. Операнды разделяются запятыми.

```asm
        DB 0x11, 0x22, 0x33      ; три байта
        DB "HELLO"               ; строка (двойные кавычки)
        DB 'A'                   ; один символ (одинарные кавычки)
        DB 1 + 2, 4 * 5          ; выражения (3, 20)
        DB CR, LF                ; 0x0D, 0x0A
        DB <">, <X>              ; zasm: литеральный текст в <...>
        DB 5 dup(0)              ; M80: 5 раз по 0
```

Поддерживаемые формы операнда:
- Числовое выражение → 1 байт (младший байт).
- Строка в `"..."` → последовательность байтов (ASCII).
- Символ в `'...'` → 1 байт; `'A'+80h` → выражение.
- `<текст>` → литеральные байты текста (zasm).
- `N dup(value)` → N повторений value (M80).
- `CR` / `LF` → 0x0D / 0x0A.
- `__date__` / `__TIME__` → текущая дата/время (zasm).

**Escape-последовательности в строках** (в одинарных и двойных кавычках):

| Последовательность | Байт | Значение |
|---|---|---|
| `\n` | 0x0A | перевод строки (LF) |
| `\t` | 0x09 | табуляция |
| `\r` | 0x0D | возврат каретки (CR) |
| `\0` | 0x00 | нулевой байт |
| `\\` | 0x5C | обратный слэш |
| `\'` | 0x27 | одинарная кавычка |
| `\"` | 0x22 | двойная кавычка |
| `\xNN` | NN | байт по шестнадцатеричному коду |

```asm
        DB "A\nB"        ; байты: 41 0A 42
        DB 'tab:\t'      ; байты: 74 61 62 3A 09
        DB "0x-код: \x41" ; байты: ... 41
```

> Escape-последовательности декодируются одинаково в `'...'` и `"..."`.
> Подсчёт длины в первом проходе согласован с генерацией во втором,
> поэтому `DB '\n'` занимает ровно 1 байт (0x0A), а не 2.

### 4.3. `DW` / `WORD` — 16-битные слова

Записывает 16-битные значения в формате **little-endian** (младший байт первым).

```asm
        DW 0x1234        ; байты: 34 12
        DW 0x1234, 0x5678  ; байты: 34 12 78 56
```

> Если операнд `DW` — **импортированный символ** (`IMPORT`), для него
> автоматически создаётся relocation-запись, и линковщик подставит
> реальный адрес.

### 4.4. `DS` / `SPACE` — резервирование пространства

Резервирует N байт, заполняя их значением по умолчанию.

```asm
        DS 8            ; 8 байт (заполнение по умолчанию)
        DS 16, 0xFF     ; 16 байт, заполнение 0xFF
```

- Значение заполнения по умолчанию зависит от `#target`:
  - `#target rom` → `0xFF`
  - `#target bin` / `ram` (по умолчанию) → `0x00`
- Второй операнд (необязательный) — явное значение заполнения.

### 4.5. `EQU` / `DEF` / `DEFL` — константы

Присваивает символу числовое значение (псевдо-метка).

```asm
        BASE     EQU 0x0200
        BUF_SIZE EQU 16
        BUF_END  EQU BASE + BUF_SIZE   ; может ссылаться на другие константы
```

- Формат: `имя EQU значение` (с двоеточием `имя: EQU значение` тоже работает).
- Константы вычисляются в момент определения; если в выражении есть ещё
  неопределённые символы, определение откладывается и вычисляется позже.
- `EQU`, `DEF`, `DEFL`, `=` — синонимы.

### 4.6. `END` — конец программы

Обозначает конец исходного текста. Всё после `END` игнорируется.

```asm
        ...
        END
```

- Необязательна: если `END` нет, ассемблер обрабатывает весь файл.
- Может иметь операнд (адрес старта), но он не используется.

### 4.7. `EXPORT` / `PUBLIC` — экспорт символов

Отмечает символы как доступные из других модулей (для линковки).

```asm
        EXPORT main, helper
        ; или
        PUBLIC main
```

- Имена указываются через запятую.
- Экспортируемый символ должен быть определён (метка или `EQU`) в этом модуле.
- При сохранении `.obj` экспортируемые символы попадают в `exports`.

### 4.8. `IMPORT` / `EXTERN` — импорт символов

Объявляет символы, которые будут определены в других модулях.

```asm
        IMPORT HELPER
        ; или
        EXTERN HELPER
```

- Имена указываются через запятую.
- Импортированный символ временно получает значение `0` (для первого прохода).
- Все 16-битные ссылки на импортированный символ (JMP, CALL, LHLD, SHLD, STA,
  LDA, Jcc, Ccc, LXI, DW) автоматически получают **relocation-запись**.
- При линковке relocation подставляет реальный адрес символа.

### 4.9. `#code` — секции (zasm)

Определяет именованную секцию с адресом и размером.

```asm
#code MAIN, 0x0100, *      ; секция MAIN, адрес 0x0100, размер авто
#code DATA, 0x0200, 0x100  ; секция DATA, адрес 0x0200, фикс. размер 0x100
```

Формат: `#code ИМЯ, АДРЕС, РАЗМЕР`, где:
- `ИМЯ` — имя секции (становится символом).
- `АДРЕС` — адрес начала секции (`*` = текущий адрес).
- `РАЗМЕР` — размер секции (`*` = автоматический, по факту занятого).

Автоматически создаются символы (для **каждой** секции, включая последнюю):
- `ИМЯ` — адрес начала секции.
- `ИМЯ_SIZE` — размер секции.
- `ИМЯ_END` — адрес конца секции.

Если размер фиксированный и код занял меньше — секция дополняется до размера
целевым байтом заполнения (0xFF для `#target rom`, 0x00 для `bin`/`ram`).

> `ИМЯ_SIZE` и `ИМЯ_END` доступны для `EQU`-констант, в том числе для
> **последней** секции: `TOTAL EQU LAST_SEC_SIZE` корректно разрешается.

## 5. Препроцессор

Препроцессор работает **до** ассемблирования и разворачивает текст.

### 5.1. `#include` — подключение файлов

Вставляет содержимое другого файла в текущую позицию.

```asm
        #include "defs.inc"      ; из кавычек
        #include <defs.inc>      ; из угловых скобок
        #include defs.inc        ; без кавычек
```

**Порядок поиска файла:**
1. Каталог текущего файла.
2. Каталоги из `#path` / `.path`.
3. Каталоги `include_dirs` (по умолчанию: каталог файла и `.`).
4. Текущий рабочий каталог (CWD).

Максимальная глубина вложенности `#include` — 16 уровней.

### 5.2. `#path` / `.path` — дополнительные каталоги поиска

Добавляет каталог в список поиска для `#include`.

```asm
        #path "inc"          ; добавить каталог inc/ (относительно текущего файла)
        #include "extra.inc" ; теперь найдётся inc/extra.inc
```

- Путь может быть относительным (от каталога текущего файла) или абсолютным.
- Работает и как `.path "inc"`.

### 5.3. `#define` — константы препроцессора

Определяет текстовую замену (макрос подстановки).

```asm
        #define PORT_OUT 0x01
        #define VERSION  2
        OUT PORT_OUT      ; → OUT 0x01
```

- Подстановка происходит **до** ассемблирования (текстовая замена).
- Значение подставляется как текст; если это не число и не в скобках —
  оборачивается в скобки.
- Подстановка не происходит внутри строк (кавычек).
- `#define` можно использовать в условиях `#if`.

> **Разница `#define` и `EQU`:** `#define` — текстовая подстановка на уровне
> препроцессора (не создаёт символ), `EQU` — числовая константа на уровне
> ассемблера (создаёт символ в таблице).

### 5.4. `#if` / `#elif` / `#else` / `#endif` — условная сборка

Условная компиляция блоков кода.

```asm
        #if VERSION >= 2
        DB "v2"
        #elif VERSION >= 1
        DB "v1"
        #else
        DB "v0"
        #endif
```

- Условие — арифметическое/логическое выражение (не ноль = истина).
- Поддерживаются `&&`, `||`, `!`, `==`, `!=`, `<`, `>`, `<=`, `>=`.
- `#define`-константы подставляются в условие.
- Вложенные `#if` поддерживаются.

Также поддерживаются формы **без `#`** (M80-стиль): `IF` / `ENDIF` / `ELSE`.

```asm
        IF VERSION >= 2
        DB "v2"
        ENDIF
```

### 5.5. `MACRO` / `ENDM` — макросы

Определяет именованный блок кода с параметрами.

```asm
        PUTCHAR MACRO CH
                MVI A, CH
                OUT PORT_OUT
        ENDM

        PUTCHAR 'A'      ; разворачивается в MVI A,'A' / OUT 0x01
```

Форматы определения:
- `ИМЯ MACRO [параметры]`
- `ИМЯ: MACRO [параметры]`
- `ИМЯ .macro [параметры]`
- `.macro ИМЯ [параметры]` / `macro ИМЯ [параметры]`

Параметры в теле макроса доступны в формах:
- `&ПАРАМ` — zasm-стиль
- `%ПАРАМ` — zasm-стиль
- `#ПАРАМ` — zasm-стиль
- `\ПАРАМ` — zasm-стиль
- `ПАРАМ` — простой (word boundary)

**Вложенные макросы** поддерживаются (макрос может вызывать другой макрос).
Максимальная глубина развёртывания — 10 уровней.

```asm
        INNER MACRO
                NOP
        ENDM
        OUTER MACRO
                INNER      ; вызовет INNER
                NOP
        ENDM
        OUTER              ; → NOP / NOP
```

### 5.6. `REPT` / `ENDM` — повторение блока

Повторяет блок кода N раз (N — целое число).

```asm
        REPT 3
                DB 0xAA
        ENDM
        ; → DB 0xAA / DB 0xAA / DB 0xAA
```

- Работает и как `.REPT 3`.
- Блок разворачивается в N **идентичных** копий (переменной счётчика нет).
- Для генерации разных значений в каждом повторении используйте макросы.

### 5.7. `#target` — целевой режим

Устанавливает режим целевого устройства (влияет на заполнение `DS`).

```asm
        #target rom      ; DS заполняется 0xFF
        #target bin      ; DS заполняется 0x00 (по умолчанию)
```

### 5.8. `#charset` — кодировка (информационно)

Указывает кодировку строк (информационная директива, не влияет на сборку).

```asm
        #charset ascii
```

### 5.9. `.8080` / `.8085` / `.asm8080` / `.asm8085` / `CPU` — тип процессора

Указывает целевой процессор. Влияет на доступные мнемоники: на 8085 доступны
`SIM`, `RIM` и недокументированные команды 8085, на 8080 — недокументированные
команды 8080 (`NOP*`, `RET*`, `CALL*`, `JMP*`). Если тип не указан, по
умолчанию считается **i8080**.

```asm
        .8080          ; Intel 8080 (по умолчанию)
        .8085          ; Intel 8085
        .asm8080       ; то же, что .8080
        .asm8085       ; то же, что .8085
        CPU 8085       ; альтернативный синтаксис
```

Директива действует с места её появления: инструкции до неё собираются под
предыдущий тип, после — под новый.

#### Пересекающиеся опкоды 8080/8085

Некоторые опкоды имеют разное значение на 8080 и 8085. Ассемблер, эмулятор и
дизассемблер разделяют их по типу процессора:

| Опкод | 8080 | 8085 |
|---|---|---|
| 0x08 | `NOP*` | `DSUB` (HL = HL - BC) |
| 0x10 | `NOP*` | `ARHL` (арифм. сдвиг HL вправо) |
| 0x18 | `NOP*` | `RDEL` |
| 0x20 | `NOP*` | `RIM` (Read Interrupt Mask) |
| 0x28 | `NOP*` | `LDHI d8` |
| 0x30 | `NOP*` | `SIM` (Set Interrupt Mask) |
| 0x38 | `NOP*` | `LDSI d8` |
| 0xCB | `JMP* a16` | `RSTV` |
| 0xD9 | `RET*` | `SHLX` ((BC) = HL) |
| 0xDD | `CALL* a16` | `JNK a16` |
| 0xED | `CALL* a16` | `LHLX` (HL = (BC)) |
| 0xFD | `CALL* a16` | `JK a16` |

Задокументированные команды 8085: `SIM` (0x30) устанавливает маску
прерываний из аккумулятора, `RIM` (0x20) читает маску прерываний в аккумулятор.
**Автоопределение:** Если в исходном коде присутствует директива типа процессора, ассемблер автоматически:
- Переключает эмулятор на соответствующий тип CPU
- Блокирует поле ручного выбора (в ассемблере и эмуляторе)
- Синхронизирует дизассемблер

При отсутствии директивы поле выбора CPU активно и пользователь может выбрать тип вручную (по умолчанию i8080).

**Флаги 8085 в эмуляторе:** При выборе i8085 в панели эмулятора дополнительно отображаются:
- `IFF1` — первый флип-флоп прерываний
- `IFF2` — второй флип-флоп прерываний  
- `I` — регистр вектора прерывания (верхний байт)


### 5.10. Информационные директивы (no-op)

Следующие директивы распознаются и игнорируются (для совместимости с M80/zasm):
`XDEF`, `XREF`, `SECTION`, `ASEG`, `TITLE`, `PUBLIC`, `EXTERN`, `MODULE`,
`LOCAL`, `ENDLOCAL`, `ERROR`, `DATA`, `BLKB`, `DISKDEF`, `IRP`, `ASSERT`,
`DEFW`, `ALIGN`, `ENDR`, `ASMPC`.

Примечание: `CPU` и `.8080`/`.8085`/`.asm8080`/`.asm8085` **не** игнорируются —
они задают тип процессора (см. 5.9).

## 6. Одиночная сборка

Одиночная сборка — ассемблирование одного `.asm` файла в один бинарник.

### Workflow

```
hello.asm ──assemble()──► AsmResult ──► hello.bin + hello.map
```

> Map-файл генерируется автоматически при каждой успешной сборке и содержит
> таблицу символов (адрес, размер, тип, имя). Он используется дизассемблером
> для расшифровки адресов в имена меток.

### Примеры

- **`assembler_example/01_hello/`** — минимальная программа (вывод строки).
- **`assembler_example/02_directives/`** — все директивы в одном файле.
- **`assembler_example/03_macros/`** — макросы, REPT, условная сборка.

### Код сборки

```python
from assemble8080.assembler import assemble
from assemble8080.mapfile import save_map_file

result = assemble(source, filename='hello.asm')
if result.success:
    open('hello.bin', 'wb').write(result.binary)
    save_map_file('hello.map', result.map_text)  # map генерируется автоматически
    print(result.symbols)   # {'START': 256, 'PRINT_STR': 263, ...}
```

### Загрузка в память эмулятора

В GUI: кнопка **Load to Memory** во вкладке «Ассемблер».
В API: см. [раздел 9](#9-инструменты-gui-api-mcp).

## 7. Многофайловая сборка и линковка

Многофайловая сборка позволяет разделить программу на модули, собрать каждый
в объектный файл (`.obj`) и слинковать в единый бинарник.

### 7.1. Концепция

```
main.asm    ──assemble()──► main.obj    (EXPORT main, IMPORT HELPER)
helper.asm  ──assemble()──► helper.obj  (EXPORT HELPER)
                              │
                              ▼
                        link() / .lnk
                              │
                              ▼
                        app.bin + app.map
```

- Каждый модуль собирается **независимо** в `.obj`.
- Модули обмениваются символами через `EXPORT` / `IMPORT`.
- Линковщик объединяет `.obj`, разрешает символы и применяет relocation.

### 7.2. Объектный файл (`.obj`)

Формат — JSON (`i8080-obj-v1`). Содержит:

| Поле | Описание |
|------|----------|
| `name` | имя модуля |
| `source` | имя исходного файла |
| `org` | базовый адрес (из `ORG`) |
| `size` | размер данных |
| `data` | hex-строка байтов |
| `symbols` | `{имя: offset_от_org}` (без IMPORT-символов) |
| `exports` | список экспортируемых имён |
| `imports` | список импортируемых имён |
| `relocations` | `[{offset, size, symbol}]` |

Создание и сохранение:

```python
from assemble8080.assembler import assemble
from assemble8080.objfile import obj_from_asm_result, save_obj, load_obj

result = assemble(source, filename='main.asm')
obj = obj_from_asm_result(result, source_name='main.asm')
save_obj('main.obj', obj)

# Загрузка обратно:
obj2 = load_obj('main.obj')
```

### 7.3. Relocation (переносимые ссылки)

Когда модуль ссылается на **импортированный** символ по 16-битному адресу,
ассемблер не знает его реальный адрес (он в другом модуле). Поэтому:

1. Ассемблер записывает адрес `0` (временный) и создаёт **relocation-запись**
   `(offset, size, symbol)`.
2. Линковщик находит реальный адрес символа (из `exports` других модулей) и
   **патчит** байты в выходном бинарнике (16-бит little-endian).

Затрагиваемые инструкции/директивы (16-битные адресные операнды):
`JMP`, `CALL`, `LHLD`, `SHLD`, `STA`, `LDA`, `Jcc`, `Ccc`, `LXI`, `DW`.

> Локальные метки (не `IMPORT`) разрешаются на этапе ассемблирования и
> relocation **не** создают.

### 7.4. Скрипт линковщика (`.lnk`)

Текстовый файл с директивами:

| Директива | Описание |
|-----------|----------|
| `INPUT f1.obj f2.obj ...` | Объектные файлы для линковки |
| `OUTPUT out.bin` | Выходной бинарный файл |
| `MAP out.map` | Генерировать map-файл |
| `ORIGIN 0x0000` | Базовый адрес вывода |
| `SIZE 0x10000` | Общий размер вывода |
| `FILL 0xFF` | Байт заполнения (гэпы) |

Пример `app.lnk`:

```
INPUT main.obj helper.obj
OUTPUT app.bin
MAP app.map
ORIGIN 0x0000
SIZE 0x10000
FILL 0xFF
```

### 7.5. Алгоритм линковщика

1. **Проверка конфликтов ORG** — два модуля не могут иметь один `ORG`.
2. **Глобальная таблица символов** — сборка всех `exports` (абсолютные адреса).
3. **Проверка неразрешённых импортов** — каждый `IMPORT` должен быть в `exports`.
4. **Выделение буфера** — размер `max(SIZE, ORIGIN + max(org+size))`.
5. **Размещение данных** — каждый `.obj` кладётся по своему `ORG`.
6. **Применение relocation** — патч 16-битных (и 8-битных) адресов.
7. **Генерация map** — таблица символов с адресами.

### 7.6. Код линковки

```python
from assemble8080.linker import link, link_from_script
from assemble8080.objfile import load_obj

# Вариант 1: по .lnk-скрипту (сам сохраняет out.bin и out.map)
result = link_from_script('app.lnk')

# Вариант 2: программно
objects = [load_obj('main.obj'), load_obj('helper.obj')]
result = link(objects, origin=0, size=0x10000, fill=0xFF)
if result.success:
    open('app.bin', 'wb').write(result.binary)
    print(result.symbols)   # {'MAIN': 256, 'HELPER': 512}
```

### 7.7. Пример

См. **`assembler_example/04_multifile/`**:
- `main.asm` — `ORG 0x0100`, `IMPORT HELPER`, `EXPORT main`, `CALL HELPER`.
- `helper.asm` — `ORG 0x0200`, `EXPORT HELPER`.
- `app.lnk` — скрипт линковщика.
- `build.py` — собирает оба модуля, слинковывает, проверяет патч `CALL`.

Результат: `app.bin` содержит `main` @ 0x0100 и `HELPER` @ 0x0200, а
`CALL HELPER` пропатчен на `0x0200` (байты `CD 00 02`).

## 8. Map-файлы

Map-файл — текстовая таблица символов с адресами. Используется для
разбора бинарника в дизассемблере (подстановка имён меток).

### 8.1. Генерация

Map-файл генерируется **автоматически** при каждой успешной сборке:

- **Одиночная сборка** — `AsmResult.map_text` заполняется ассемблером.
  GUI и API сохраняют `.map` файл рядом с исходным (например, `hello.asm` → `hello.map`).
- **Линковка** — `LinkResult.map_text` заполняется линковщиком (объединённая таблица).

```python
from assemble8080.assembler import assemble
from assemble8080.mapfile import save_map_file, load_map_file

result = assemble(source, filename='hello.asm')
if result.success:
    # map_text уже сгенерирован
    save_map_file('hello.map', result.map_text)

# Из результата линковки:
map_text = link_result.map_text   # уже сгенерирован линковщиком
```

Формат map-файла (текст v1):

```
; Map file v1
; Source: hello.asm
; Date: 2026-09-22
; ORG: 0x0100
; Size: 0x0019
0x0100  START
0x0107  PRINT_STR
0x0112  DONE
0x0113  MSG
```

### 8.2. Загрузка и использование

```python
from assemble8080.mapfile import load_map_file

mf = load_map_file('hello.map')
mf.get_symbol_at(0x0108)    # 'START' (символ по или до адреса)
mf.get_symbol_exact(0x0107) # 'PRINT_STR' (точно по адресу)
mf.to_dict()                # {0x0100: 'START', 0x0107: 'PRINT_STR', ...}
```

### 8.3. Загрузка в дизассемблер (GUI)

1. Откройте вкладку **«Дизассемблер»**.
2. Нажмите **Load Map** и выберите `.map` файл.
3. Дизассемблер подставит имена меток и разрешит адреса переходов.

В API: `asm_load_map(path)` (см. [раздел 9](#9-инструменты-gui-api-mcp)).

## ## Поддержка Intel 8085

Ассемблер поддерживает директивы выбора типа процессора:

| Директива | Описание |
|-----------|----------|
| `.8080` / `.asm8080` | Установить CPU = i8080 |
| `.8085` / `.asm8085` | Установить CPU = i8085 |
| `CPU 8080` / `CPU 8085` | Установить CPU (альтернативный синтаксис) |

По умолчанию: **i8080**.

### Команды 8085 (недоступны на 8080)

| Мнемоника | Опкод | Байты | Описание |
|-----------|-------|-------|----------|
| `SIM` | 0x20 | 1 | Set Interrupt Mask — установить маску прерываний |
| `RIM` | 0x30 | 1 | Read Interrupt Mask — прочитать маску прерываний |
| `DSUB` | 0x08 | 1 | HL = HL - BC (недокументированная) |
| `ARHL` | 0x10 | 1 | Арифметический сдвиг HL вправо (недокументированная) |
| `RDEL` | 0x18 | 1 | Недокументированная (NOP) |
| `LDHI d8` | 0x28 | 2 | Недокументированная (загрузка d8) |
| `LDSI d8` | 0x38 | 2 | Недокументированная (загрузка d8) |
| `RSTV` | 0xCB | 1 | Недокументированная (NOP) |
| `SHLX` | 0xD9 | 1 | (BC) = HL (недокументированная) |
| `JNK a16` | 0xDD | 3 | Недокументированный переход |
| `LHLX` | 0xED | 1 | HL = (BC) (недокументированная) |
| `JK a16` | 0xFD | 3 | Недокументированный переход |

### Команды 8080 (недоступны на 8085)

| Мнемоника | Опкод | Байты | Описание |
|-----------|-------|-------|----------|
| `NOP*` | 0x08,0x10,0x18,0x20,0x28,0x30,0x38 | 1 | Недокументированные NOP |
| `JMP* a16` | 0xCB | 3 | Недокументированный JMP (без push) |
| `RET*` | 0xD9 | 1 | Недокументированный RET |
| `CALL* a16` | 0xDD,0xED,0xFD | 3 | Недокументированный CALL |

### Пример

```asm
; 8085-программа с прерываниями
.8085
    ORG 100H
START:
    SIM           ; Разрешить прерывания, маска = 111b
    MVI A, 0FFH
    RIM           ; Прочитать состояние прерываний
    JMP START
```


## Быстрая справка (cheat sheet)

```asm
; === Каркас программы ===
        ORG 0x0100          ; базовый адрес
        #define CONST 0x10  ; константа препроцессора
        BASE EQU 0x0200     ; константа ассемблера
        #include "defs.inc" ; подключение файла
        #path "inc"         ; каталог поиска
        EXPORT main         ; экспорт для линковки
        IMPORT helper       ; импорт из другого модуля

main::
        MVI A, CONST        ; инструкция
        CALL helper         ; вызов (relocation при IMPORT)
        HLT                 ; остановка

; === Макрос ===
        PUT MACRO CH
                MVI A, CH
                OUT 0x01
        ENDM
        PUT 'A'

; === Повторение ===
        REPT 4
                DB 0
        ENDM

; === Условная сборка ===
        #if CONST >= 0x10
        DB "big"
        #else
        DB "small"
        #endif

        END                 ; конец программы
```
